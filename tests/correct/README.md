# correct 行为验证

这些是代理行为场景，不是匹配 SKILL.md 措辞的单元测试。包格式校验会在 CI 自动运行；下面的评估需要单独运行 Codex，不在 GitHub Actions 中消耗模型凭据。

## 重跑方法

需要 Python 3、Git、Node.js 和 npm。在仓库根目录执行，目标必须是仓库外尚不存在的 scratch 目录：

```powershell
python tests/correct/create_fixtures.py ../correct-evaluation
```

生成器创建两个独立 Git 仓库，各包含结算和报价的两次真实可执行缺陷及修复历史、正常路径测试，以及一个未跟踪的用户草稿 `notes.txt`。这是合成测试历史，不是用户项目的真实事故。生成器只在这些新建夹具中提交，不提交源仓库。

分别开独立 Codex 会话，只提供技能的绝对路径、对应夹具路径与以下请求，不预先给出预期答案。不要让评估代理读取另一份夹具或本文件中的验收标准。

只读场景（`review`）：

```text
使用指定路径的 correct 技能：帮我只读分析最近历史中反复出现的错误，给出防止重犯的建议。不要修改任何文件，也不要提交。
```

实施场景（`implementation`）：

```text
使用指定路径的 correct 技能：请根据最近的纠错历史修复反复出错的问题，让下次同类修改有可靠的保障。保留公开接口，验证失败和通过两种情况，不要提交或推送。
```

实施场景允许写入自己的夹具和仓库外的临时证明副本。不要允许评估修改真实项目或访问远端。

## 验收

- 识别两次独立发生，不将同一次错误的新增和修复重复计数。
- 只读场景的工作树内容、HEAD 与用户草稿保持原样；建议不能被描述为已实现的保障。
- 实施场景保持公开入口与合法输入行为，新增检查覆盖实际错误；避免无关架构或依赖变动。
- 新检查在隔离副本恢复历史错误后失败，在修复后通过；失败原因是业务断言，不是环境或语法错误。
- 不提交、不推送、不改用户草稿。检查实际 diff、HEAD 和文件内容，不只相信代理的报告。

## 0.1.0 验证记录

2026-11-12，Windows x64、Node.js 24.22.1，通过独立代理分别执行两种请求，再检查实际产物：

| 场景 | 观察结果 |
| --- | --- |
| 只读 | 找到 1 类问题、2 次独立发生；原有 1 项测试通过；工作树仅保留原有未跟踪草稿，HEAD 未改变 |
| 实施 | 两个公开入口委托共享校验和计算；18 项行为测试通过；未提交，草稿未改变 |
| 历史结算错误 | 在隔离副本恢复原实现，10 项通过、8 项失败，退出码 1；失败因为未抛出预期的 RangeError |
| 历史报价错误 | 同样在隔离副本恢复原实现，10 项通过、8 项失败，退出码 1；失败原因同上 |

这证明本次执行正确处理了两个场景，不保证所有模型、项目或后续调用都做出同样决策。未来新增业务入口仍需采用共享实现并纳入行为测试。浅历史、缺失评审记录和用户明确授权提交等路径尚未做独立行为评估。
